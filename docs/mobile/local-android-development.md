# Local Android Development — Canonical Runbook

> **FOMO-173.** This is the canonical, start-to-finish guide for developing the
> FOMO mobile app on Android from a fresh Windows machine. If this document and
> any other document disagree, this document wins. Companion documents:
>
> - Troubleshooting & recovery: [android-expo-debugging-guide.md](./android-expo-debugging-guide.md)
> - Staging services & environment values: [staging-mobile-setup.md](./staging-mobile-setup.md)

## 1. Purpose and supported workflow

The supported everyday workflow is a **local Android debug build** of the
committed native project, installed on a device, loading JavaScript from a
local **Metro** dev server over USB (`adb reverse`). You compile natively once,
then iterate on TypeScript with Fast Refresh. **Expo Go is not supported** as
the canonical environment (see §29).

## 2. Current project model

`apps/mobile/android/` is a **committed, hand-maintained** native project. It
was originally generated by `expo prebuild`, then modified with required
monorepo/Windows fixes (Ninja/CMake injection, worklets-core resolution). It is
canonical source, not a build artifact.

> ⛔ **Never run `expo prebuild` or `expo prebuild --clean`** for routine work —
> regeneration destroys the hand-maintained fixes. See §30.

There is no committed `ios/` project yet (see §33).

## 3. Supported platforms and current MVP scope

FOMO is a cross-platform **Android + iOS** product. **Android is the active MVP
development target**; iOS native development begins after the Android MVP
(§33). The physical acceptance device for Android is a **OnePlus 12**.

| Component | Version | Defined by |

| New Architecture (Fabric/TurboModules) | enabled | `android/gradle.properties` |
| Ninja (Windows only) | **1.13.2+** at `C:\ninja\ninja.exe` (§8) | this contract; CORE_RULES.md |

Notes:

- **Node 20 is the contract but is not yet enforced locally** (no `engines`
  field); CI uses Node 20. Don't rely on other majors working.
- **Android compileSdk / targetSdk / minSdk / build-tools / NDK / AGP / Kotlin
  are not pinned in this repository.** They resolve transitively from the Expo
  SDK 54 Gradle plugins (`expoAutolinking.useExpoVersionCatalog()` in
  `android/settings.gradle`), which the lockfile pins via the `expo` package
  version. To inspect the resolved values when needed (from
  `apps/mobile/android`):

  ```powershell
  # compileSdk / targetSdk / minSdk / buildTools / ndk (root ext properties)
  .\gradlew.bat properties | Select-String -Pattern "SdkVersion|buildTools|ndk"

  # Android Gradle Plugin / Kotlin plugin versions on the buildscript classpath
  .\gradlew.bat buildEnvironment
  ```

## 6. JDK 21 configuration

Gradle selects its JVM from **`JAVA_HOME`**. No JDK path is committed to the
repository (`org.gradle.java.home` is intentionally absent from tracked files).

```powershell
# Per-session (or set JAVA_HOME system-wide in Windows environment settings)
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

Verification:

```powershell
$env:JAVA_HOME
& "$env:JAVA_HOME\bin\java.exe" -version    # must report 21.x
& "$env:JAVA_HOME\bin\javac.exe" -version   # must report 21.x
where.exe java

Set-Location apps\mobile\android
.\gradlew.bat --version
```

`gradlew.bat --version` must report a **21.x Launcher JVM** and a Daemon JVM
resolved from "current Java home". Important:

- **`JAVA_HOME` is authoritative.** Plain `java -version` can lie: on machines
  where Oracle's `javapath` shim precedes `JAVA_HOME` on PATH, it reports a
  different JDK than the one Gradle uses. Always verify via
  `$env:JAVA_HOME\bin\java.exe`.
- **Never commit** `org.gradle.java.home` (or any absolute JDK path) to tracked
  files. If a machine-specific override is unavoidable, it belongs in your
  user-level `$HOME\.gradle\gradle.properties`.

## 7. Android SDK and platform tools

- Install the Android SDK via **Android Studio** (or standalone command-line
  tools).
- Set `ANDROID_HOME` to `%LOCALAPPDATA%\Android\Sdk`.
- Ensure `platform-tools` (adb) is on PATH: `adb version` must work.

## 8. Windows Ninja requirement

Windows native builds require **Ninja 1.13.2 or newer at exactly
`C:\ninja\ninja.exe`**:

1. Download the `ninja-win.zip` release binary (v1.13.2+) from the official
   Ninja releases page.
2. Extract to `C:\ninja\ninja.exe`.
3. Verify:

   ```powershell
   C:\ninja\ninja.exe --version   # 1.13.2 or newer
   ```

Why: React Native/CMake native builds under long pnpm store paths hit the
Android SDK's bundled Ninja 1.10 250-character object-path cap, producing
`manifest 'build.ninja' still dirty after 100 tries`. The committed Gradle
scripts inject `-DCMAKE_MAKE_PROGRAM=C:/ninja/ninja.exe` and
`-DCMAKE_OBJECT_PATH_MAX=1024` **only when Gradle runs on a Windows host**
(`isWindowsHost` in `android/build.gradle`). Linux/macOS hosts use their normal
toolchain resolution and never receive this path. `CMAKE_OBJECT_PATH_MAX=1024`
is Windows-specific. Do not edit or regenerate these Gradle files.

## 9. Windows long-path requirement

Enable NTFS long paths (once, as admin):
`HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem` →
`LongPathsEnabled` = `1` (then reboot). Without it, deep pnpm paths break
native compilation.

## 10. Environment-file setup

```powershell
Copy-Item apps\mobile\.env.example apps\mobile\.env
```

Then edit `apps/mobile/.env` with real values (staging values:
[staging-mobile-setup.md](./staging-mobile-setup.md)). `.env` is git-ignored —
**never commit it**. After changing `.env`, restart Metro with
`pnpm --filter @fomo/mobile start:clear` (§25).

## 11. Environment-variable reference

`apps/mobile/.env.example` is the canonical list of variable names. All app
variables are **public runtime configuration**:

| Variable | Consumed by | Purpose |
|---|---|---|
| `EXPO_PUBLIC_API_URL` | `utils/api-client.ts`, auth provider | Backend REST base URL |
| `EXPO_PUBLIC_AUTH_URL` | `utils/auth-client.ts` | Keycloak base URL |
| `EXPO_PUBLIC_KEYCLOAK_REALM` | `utils/auth-client.ts` | `fomo-users` (never `fomo-admin`) |
| `EXPO_PUBLIC_KEYCLOAK_CLIENT_ID` | `utils/auth-client.ts` | `fomo-mobile` public PKCE client |
| `EXPO_PUBLIC_AUTH_REDIRECT_SCHEME` | `utils/auth-client.ts` | `fomo` — must match `app.json` `scheme` |
| `EXPO_PUBLIC_MAPBOX_TOKEN` | `components/fomo/fomo-map.tsx` | Mapbox **public** `pk.*` token (§12) |
| `EXPO_PUBLIC_DEFAULT_LAT` / `_LNG` / `_RADIUS_KM` | `utils/location-config.ts` | Discovery fallback coordinates |
| `EXPO_PUBLIC_PERF_DEBUG` | perf instrumentation | Optional debug flag (default off) |
| `EXPO_PUBLIC_PERF_RENDER_DEBUG` | perf instrumentation | Optional debug flag (default off) |

> ⚠️ **Every `EXPO_PUBLIC_*` value is embedded in the client JavaScript bundle
> at build time.** They are, by definition, public. **None of them may ever
> contain a secret.**

The only build-time secret candidate is the Mapbox native download token
(§13) — it is *not* an app variable and never goes in `.env`.

## 12. Mapbox public/runtime token

`EXPO_PUBLIC_MAPBOX_TOKEN` must be a **public `pk.*` token**, restricted to the
app's bundle ID in the Mapbox dashboard. It is embedded in the bundle and used
at runtime to fetch map tiles. If it is missing/invalid, the app still runs but
the map area renders as a dark placeholder.

## 13. Mapbox native download token

A separate **secret `sk.*` token** (`MAPBOX_DOWNLOADS_TOKEN` Gradle property,
or `RNMAPBOX_MAPS_DOWNLOAD_TOKEN` environment variable) authenticates Gradle's
download of the native Mapbox Maps SDK artifacts during **native compilation
only**. Facts, stated precisely:

- Lint, TypeScript, and Metro-only JS work **never** need it.
- The committed Gradle config treats it as **optional** (auth is applied only
  when the property is present).
- A successful incremental debug build (FOMO-173 Phase 1A) ran **with no token
  configured at all** — but the Mapbox artifacts were already in the local
  Gradle cache, so **whether an empty-cache build needs the token remains
  inconclusive**. Do not assume it is optional.
- If you configure it, store it **only** in user-level
  `$HOME\.gradle\gradle.properties` (`MAPBOX_DOWNLOADS_TOKEN=sk.…`) or as an
  environment variable. **Never commit it; never put it in `.env`.**

## 14. Physical Android device preparation

Canonical acceptance device: **OnePlus 12**. Any recent Android phone works
for development.

1. **Enable USB debugging**: Settings → About phone → tap *Build number* 7× →
   Developer Options → *USB debugging* on.
2. Connect via USB; accept the *Allow USB debugging?* RSA prompt on the phone.
3. **Windows drivers**: if the device never appears, install the OEM USB
   driver (OnePlus devices generally work with the standard Google/ADB driver;
   check Device Manager for unrecognized devices).
4. Verify:

   ```powershell
   adb devices -l
   ```

   The device must show state `device`. `unauthorized` means re-accept the RSA
   prompt on the phone; `offline` means replug the cable.
5. **Multiple devices/emulators connected**: every `adb` command becomes
   ambiguous. Find the serial in `adb devices -l` and target it explicitly:

   ```powershell
   $deviceSerial = "<adb-serial>"
   adb -s $deviceSerial ...
   ```

## 15. Emulator status and limitations

An Android Studio AVD (x86_64 is included in `reactNativeArchitectures`)
should work for general development, but the emulator path is **not separately
validated** and is not the acceptance path — physical-device validation on the
OnePlus 12 is. Location, maps performance, and auth browser redirects behave
differently on emulators; validate on hardware before calling anything done.

## 16. First native debug build

From the repository root, with `JAVA_HOME` set (§6) and the device connected:

```powershell
Set-Location C:\fomo-monorepo\apps\mobile\android
.\gradlew.bat :app:assembleDebug --no-daemon --stacktrace
```

- First build downloads dependencies and compiles native code for all ABIs —
  expect it to be slow (tens of minutes); incremental rebuilds are ~1 minute.
- Do **not** run `clean` by default (§26).
- Expected result: `BUILD SUCCESSFUL`, APK at
  `apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

## 17. APK build and manual installation

```powershell
adb -s $deviceSerial install -r `
  ".\app\build\outputs\apk\debug\app-debug.apk"
```

The installed package is **`com.fomo.mobile`**.

**Convenience alternative** (from repo root):

```powershell
pnpm --filter @fomo/mobile android
```

This invokes `expo run:android`, which builds **and** installs, and may start
Metro for you. It is fine for everyday use; prefer the raw
`gradlew :app:assembleDebug` form when you need an isolated, diagnosable
native build (clean exit code, full log, no Metro side effects).

## 18. Metro startup

From the repository root:

```powershell
pnpm --filter @fomo/mobile start
```

Rules:

- **Exactly one Metro process owns port 8081.** If Metro is already running
  from a previous session (the CLI reports "Port 8081 is being used"), reuse
  the existing instance — do not kill it unnecessarily, and do not accept an
  alternate port (the installed app expects 8081).
- Expo Go is not used; ignore the QR-code path.

## 19. adb reverse

Physical devices reach Metro through a reverse USB tunnel. Run after every
device reconnect:

```powershell
adb -s $deviceSerial reverse tcp:8081 tcp:8081
adb -s $deviceSerial reverse --list   # must show: tcp:8081 tcp:8081
```

## 20. Application launch

Open **FOMO** on the device (or:
`adb -s $deviceSerial shell monkey -p com.fomo.mobile -c android.intent.category.LAUNCHER 1`).
A debug build always loads its JavaScript from Metro — the Metro terminal
shows a bundling progress bar on first connect. If the app hangs on a spinner,
re-check §19, then see the
[troubleshooting guide](./android-expo-debugging-guide.md).

## 21. Authentication redirect validation

The app is login-gated. Tap *Continue with Google*: a Chrome Custom Tab opens
Keycloak, and after consent the browser must redirect back into the app via
the **`fomo://` scheme** (registered in `app.json` and the Android manifest of
package `com.fomo.mobile`). Dev builds log the redirect URI at startup
(`[auth] redirect URI: fomo://…`). Keycloak client configuration lives in
[mobile-auth-keycloak.md](./mobile-auth-keycloak.md).

Auth is only considered validated on a **native build on a physical device** —
never under Expo Go (different redirect model, §29).

## 22. Mapbox validation

With a valid `pk.*` token in `.env`, the Discover tab renders the dark Mapbox
map with event pins. A dark, empty map placeholder means the token is missing
or invalid (§12) — the rest of the app still works.

## 23. Daily JavaScript development loop

1. Native debug build installed once (§16–17).
2. Start or reuse Metro (§18).
3. Ensure `adb reverse` (§19).
4. Edit TypeScript/React files — Fast Refresh applies them automatically
   (or press `r` in the Metro terminal / shake device → Reload).
5. Rebuild the native APK only for the changes in §24.

## 24. Changes requiring native rebuild

| Change type | Metro reload | Native rebuild |
|---|---|---|
| TS/TSX UI or logic | ✅ | — |
| Styling / theme / NativeWind classes | ✅ | — |
| `.env` value | ✅ via `start:clear` (§25) | — |
| `app.json` (plugins, scheme, permissions…) | — | ✅ |
| New/updated dependency **with native code** | — | ✅ |
| Pure-JS dependency | ✅ (restart Metro) | — |
| `AndroidManifest.xml` | — | ✅ |
| Any Gradle file | — | ✅ |
| Java/Kotlin/C++ source | — | ✅ |
| `@rnmapbox/maps` (or any native module) version bump | — | ✅ |

## 25. Safe cache-clearing sequence

When JS changes don't appear or `.env` changed:

```powershell
pnpm --filter @fomo/mobile start:clear   # Metro with reset cache
```

Then reload the app. If stale UI persists, the device may be running an
embedded bundle instead of Metro — see the definitive recovery sequence in the
[troubleshooting guide](./android-expo-debugging-guide.md#common-errors).

## 26. Safe build-output cleanup

Safe to delete (all git-ignored, regenerated by the next build):

```powershell
Remove-Item -Recurse -Force apps\mobile\android\app\build
Remove-Item -Recurse -Force apps\mobile\android\app\.cxx
```

Prefer deleting these directories over `gradlew clean` on Windows (the CMake
clean task itself can fail; see troubleshooting guide). Never delete or
regenerate `apps/mobile/android/` itself — it is source (§2).

## 27. Debug versus release behavior

- **Debug** (`assembleDebug`, the canonical build): loads JS from Metro,
  supports Fast Refresh and dev tooling.
- **Release** (`assembleRelease`): embeds a static JS bundle — it never
  contacts Metro, so JS edits have no effect until rebuilt. Use only for local
  release-mode validation (performance measurements, Metro-free startup).

## 28. Production-signing warning

> ⛔ **The `release` buildType currently signs with the tracked debug keystore**
> (publicly known credentials). Any release APK is **local validation only**:
> never distribute it, never upload it to Google Play. Production Android
> signing is deferred; Apple signing/TestFlight/App Store are likewise
> deferred (§33). `debug.keystore` is accepted in the repository **only** for
> development builds.

## 29. Expo Go limitations

Expo Go cannot load this app's required native modules (`@rnmapbox/maps`;
`expo-location` prompts also behave differently), and its `exp://` redirect
model does not match the app's registered `fomo://` scheme, so authentication
is unvalidated there. Expo Go is therefore **not part of the supported
workflow**. Do not report bugs or validate features against Expo Go.

## 30. expo prebuild prohibition

`expo prebuild` / `expo prebuild --clean` **regenerate `android/` from
app.json and would silently delete** the hand-maintained monorepo/Windows
fixes (host-conditional Ninja/CMake injection, worklets-core resolution).
They are forbidden for routine work. Any future intentional regeneration is an
engineering task that must re-apply and re-validate every manual fix.

## 31. Jenkins ownership and current CI boundary

**Jenkins is the active CI owner**; its pipelines live in the `fomo-platform`
repository. As of FOMO-173 Phase 2 there is **no mobile CI gate yet**: native
builds are manual, and mobile lint/type checks run locally only. Phase 3 adds
deterministic mobile quality commands for Jenkins to call; a later Jenkins job
may build and archive an APK. Native compilation will not run on every CI
change initially.

## 32. EAS status

**EAS is not configured** (no `eas.json`, no EAS project, no `expo-updates`),
and nothing in this repository depends on it. Adopting EAS
(development/preview builds) is optional and explicitly deferred.

## 33. iOS roadmap

- iOS is a supported product target; there is **no committed `ios/` project
  yet**. Android MVP comes first.
- Future iOS development will use a **MacBook Pro + Xcode + a physical
  iPhone**. A free Apple account may support limited personal-device
  development; **TestFlight/App Store distribution requires the paid Apple
  Developer Program** (enrollment deferred until after the Android MVP).
- Do not run `expo prebuild` to create `ios/` ad hoc — the iOS native-source
  strategy (committed vs generated, and how the Android-style manual fixes
  translate) must be designed first.

## 34. Common failures

See the [Android + Expo debugging guide](./android-expo-debugging-guide.md)
for the full catalogue: Metro unreachable, stale-bundle recovery, Gradle/CMake
cache resets, Keycloak errors, location-permission quirks, logcat recipes.
Quick hits: app stuck on spinner → §19; map is a dark placeholder → §12/§22;
`build.ninja still dirty` → §8; wrong-JDK build errors → §6.

## 35. Verification checklist

A fresh setup is complete when all of these pass:

- [ ] `pnpm install` completes from repo root
- [ ] `$env:JAVA_HOME\bin\java.exe -version` reports 21.x
- [ ] `.\gradlew.bat --version` reports Gradle 8.14.3 on a 21.x JVM
- [ ] `C:\ninja\ninja.exe --version` reports ≥ 1.13.2 (Windows)
- [ ] `adb devices -l` shows the phone in `device` state
- [ ] `:app:assembleDebug` → `BUILD SUCCESSFUL`
- [ ] `adb install -r …app-debug.apk` → `Success`
- [ ] `adb reverse --list` shows `tcp:8081 tcp:8081`
- [ ] App launches; Metro terminal shows a bundle being served
- [ ] Login completes and returns via `fomo://` redirect
- [ ] Discover renders the Mapbox map (no dark placeholder)
- [ ] A trivial TS edit hot-reloads without a native rebuild
- [ ] `pnpm --filter @fomo/mobile lint` and
      `pnpm --filter @fomo/mobile exec tsc --noEmit` pass

```powershell

# Native debug build (from apps\mobile\android, JAVA_HOME set)
```
